# Сверка версий — рабочий журнал отличий 1.0 ↔ 2.0 ↔ 3.0

Живая память о том, чем версии отличаются и **как задуманное будет работать**.
Пополняется прямо сейчас, по ходу работы над 1.0, — чтобы к моменту сборки
следующих версий ни одна идея и ни одно отложенное решение не всплыло из памяти.

**Чем отличается от паспорта.** Страница `/version` (`app/version/page.tsx`) —
короткая витрина для автора: что умеет, что впереди. Этот файл — подробный
рабочий чертёж для сборки: с идеями реализации, зацепками в коде и открытыми
вопросами. Витрина — для читателя, чертёж — для мастера.

**Как ведётся.** Правило в `CLAUDE.md`: как только принимается решение «это
упрощаем / откладываем до следующей версии», строка и заметка появляются здесь
в тот же момент, без отдельной просьбы (как `handoff.md` и слияние в `main`).

## Быстрый обзор

| Область | В 1.0 | В 2.0 | Почему отложили | Зацепки в коде |
|---|---|---|---|---|
| Разбор от ИИ | Копирование депеши туда-обратно вручную | Личный API-ключ — ответ приходит сам | Нет ключей/бэкенда в 1.0 | `components/PassActions.tsx`, `lib/aiLink.ts`, `lib/prompts.ts` |
| Аудит голоса | «Сверка голоса» — лёгкое зеркало, без файлов | Полный аудит корпуса: авто-ядро, авто-замеры, история | Тяжёлая машинерия, не нужна для первого запуска | `lib/prompts.ts` (`buildAuditPrompt`), `lib/audit.ts` (`buildAuditMarkdown`, `writeAuditFile`) — оставлены, тесты живы |
| Наставники | Трое (Чехов, Довлатов, Соркин) | Плюс свои наставники под свой вкус и жанр | Нужен редактор наставника и хранилище | `lib/compasses.ts` (`ACTIVE_COMPASS_IDS`, `COMPASSES`), `learning/compasses/*.md` |
| Замеры наставников (дельты) | Статичные таблицы из md-файлов, вручную | Аудит заполняет дельты сам | Часть полного аудита | `lib/deltas.ts` (`readDeltaTables`, `extractDeltaTable`) |
| Доступ | Локально, на компьютере автора | (3.0) Доступ по ссылке | Нужен хостинг + база данных | — |

## Версия 2.0 — автономная мастерская (подробно)

### Личный API-ключ — автономный разбор

- **Как в 1.0.** Ритуал «приватной переписки»: автор жмёт «Передать депешу»
  (копируется промпт), вставляет его в свою ИИ вручную, копирует ответ и
  вставляет обратно в окно. Промпт «упакован» — не показывается на экране.
- **Как задумано в 2.0.** Автор один раз вписывает свой API-ключ (свой сервис
  ИИ). Дальше приложение само отправляет депешу и получает ответ — копировать
  туда-обратно не нужно. Это и есть «более автономная, автоматизированная
  версия».
- **Идеи реализации.**
  - Ключ хранится только у автора (как сейчас адрес ИИ — в браузере/локально),
    наружу не уходит; проект остаётся «своим кабинетом».
  - Выбор сервиса (несколько провайдеров ИИ) + поле ключа в настройках.
  - Тот же слой промптов (`lib/prompts.ts`) переиспользуется — меняется только
    доставка: вместо «скопировать» — вызов API. Разбор ответа (`parsePromptResponse`)
    остаётся тем же контрактом `===IRINAOS===`.
  - Ручной режим (копирование) стоит оставить как запасной — для тех, у кого
    ключа нет.
- **Зацепки в коде.** `components/PassActions.tsx` (ритуал копирования),
  `lib/aiLink.ts` (адрес сервиса), `lib/prompts.ts` (сборка + контракт).
- **Открытые вопросы.** Какие провайдеры на старте; где хранить ключ
  безопасно; что показывать, пока идёт запрос.

### Свои наставники

- **Как в 1.0.** Трое задействованных (Чехов, Довлатов, Соркин), остальные из
  13 — в подвале «встретиться в следующих версиях». Знание каждого — в
  md-файле `learning/compasses/*.md`. Своих добавить нельзя.
- **Как задумано в 2.0.** Автор добавляет своего наставника — мастера под свой
  вкус и жанр.
- **Идеи реализации.**
  - Редактор наставника: имя, родной жанр, оси, текст-знание (как в
    существующих md-компасах).
  - Хранить рядом с авторскими данными (папка `data/`, вне git), чтобы
    обновление кода не затирало.
  - Активные наставники перестают быть жёстким списком из трёх.
- **Зацепки в коде.** `lib/compasses.ts` (`ACTIVE_COMPASS_IDS`, `COMPASSES`,
  `CompassMeta`), `learning/compasses/*.md` (формат знания), `lib/passMeta.ts`
  (`COMPASS_TITLES`).
- **Открытые вопросы.** Насколько глубоко автор задаёт «оси»; можно ли клонировать
  готового наставника и подправить.

### Полный аудит корпуса (из «Сверки голоса»)

- **Как в 1.0.** «Сверка голоса» — лёгкое зеркало: секретарь смотрит пары
  «было ↔ стало» и называет 2–3 повторяющиеся черты правок. Файлов не пишет,
  «ядро голоса» и замеры не ведёт — выводы делает автор.
- **Как задумано в 2.0.** Сверка дорастает до полного аудита, который сам:
  - ведёт **«ядро голоса»** — подтверждённые механики по правилу «2–3 повтора
    на разных текстах»;
  - **заполняет дельты** наставников (замеры на странице «Наставники»);
  - копит **историю аудитов** (архив md).
- **Идеи реализации.**
  - Вернуть тяжёлую депешу аудита (`buildAuditPrompt`) и запись файла
    (`buildAuditMarkdown` / `writeAuditFile`) — они уже оставлены в коде и под
    тестами, специально не выброшены.
  - Дату последнего аудита снова можно брать из md-файлов ИЛИ с прохода (сейчас
    работает `lastVoiceCheckDate` + `laterDate` — совместимо с обоими).
  - Авто-заполнение дельт: из секции ответа аудита писать в `## …DELTA…`
    md-файлов компасов (сейчас `readDeltaTables` только читает).
- **Зацепки в коде.** `lib/prompts.ts` (`buildAuditPrompt`), `lib/audit.ts`
  (`buildAuditMarkdown`, `writeAuditFile`, `AUDITS_DIR`), `lib/rituals.ts`
  (`readLastAuditDate`), `lib/deltas.ts` (запись дельт), `app/desk/actions.ts`
  (`startVoiceCheck` → расширить до полного аудита).
- **Открытые вопросы.** Уживаются ли «Сверка» (лёгкая) и «Аудит» (полный)
  вместе, или полный заменяет лёгкий; как показывать авто-обновление ядра.

## Версия 3.0 — наброски

### Доступ по ссылке

- **Как в 1.0.** Приложение работает локально, на компьютере автора; данные —
  тоже только у него (`data/`, вне git).
- **Как задумано в 3.0.** Работать не только на своём компьютере — доступ по
  ссылке, чтобы тестировщики и читатели могли зайти.
- **Идеи реализации (черновик).**
  - Нужен хостинг (деплой приложения) и база данных вместо локальных json.
  - Разделение данных по авторам (у каждого — свой кабинет).
  - Отсюда же вырастает разговор о коммерческом формате.
- **Открытые вопросы.** Одна база или несколько; как переносить локальные
  тетради автора в облако; приватность текстов.

### Ещё идеи (складываем сюда, чтобы не потерять)

- Совместная работа за одним столом (обсуждали как возможное направление).
- **Дельта как нарратив с накоплением.** В 1.0 «Как растёт голос» —
  осевая дельта из накопленных разборов (`lib/axisDelta.ts`: окрепло/в работе
  по осям, с базой «основано на N сверках»). В 2.0: авто-«письмо роста» —
  связный рассказ о движении голоса круг к кругу + вехи роста (нужна генерация
  из накопленных axisResult). Зацепка: `lib/axisDelta.ts`, страница «Наставники».
- **Копилка упражнений.** В 1.0 микроупражнение из разбора «Сверить» просто
  показывается в конце разбора (в копилку — по желанию, вне приложения). В 2.0:
  отдельное место в Кабинете, где эти упражнения копятся из всех сверок —
  личный тренажёр микронавыков по осям наставников. Зацепка: `[УПРАЖНЕНИЕ]` в
  `parseCompassResponse`, `parsedResult["упражнение"]`.
- **Живой голос секретаря.** В 1.0 реплики секретаря — конечные пулы с
  случайным выбором (`lib/secretaryLines.ts`), т.к. приложение само ИИ не
  зовёт. В 2.0 (со своим API-ключом) реплики можно **генерить на лету** под
  ситуацию (сколько дней не был, что правил, темп) — свежо и без повторов.
  Зацепка: `lib/secretaryLines.ts` (пулы → заменить/дополнить генерацией).
- (Дополняем по ходу.)
